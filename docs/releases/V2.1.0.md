## Périmètre V2.1

### 1. Navigation entre processus autonomes

- Garder les sous-processus BPMN intégrés pour la décomposition interne d'un diagramme.
- Ajouter une navigation explicite depuis une Call Activity vers un processus indépendant du référentiel.
- Un lien doit cibler un identifiant stable de ressource, pas uniquement un nom de processus.
- Prévoir le retour au processus appelant et une indication de navigation (fil d'Ariane ou historique).
- Les liens peuvent viser un processus commun ou un processus spécifique à un projet.
- Un processus commun reste partagé ; un clone reste indépendant et ne remplace pas implicitement la cible commune.

### 2. Contrôle d'accès

- Vérifier côté serveur que l'utilisateur peut lire le processus cible à chaque ouverture.
- Si l'accès est refusé, garder le processus source ouvert et afficher un message explicite, sans divulguer les détails d'une ressource interdite.
- Traiter séparément les références invalides, supprimées ou indisponibles.
- Ne pas compter sur un contrôle uniquement côté interface.

### 3. Filiation et comparaison d'un clone

- Conserver l'identifiant du processus source lors du clonage, si la donnée n'est pas déjà présente dans le modèle actuel.
- Depuis le clone, permettre d'ouvrir le comparateur existant avec le processus source.
- Comparer les éléments BPMN et leurs propriétés métier ; éviter de présenter les changements d'identifiants techniques ou de coordonnées graphiques comme des changements métier.
- La comparaison est en lecture seule dans la première version ; aucune fusion automatique.

## Critères d'acceptation obligatoires

- [ ] Une Call Activity liée à un processus accessible ouvre la bonne ressource.
- [ ] Le retour vers le processus appelant fonctionne.
- [ ] La navigation vers un processus commun fonctionne pour un utilisateur autorisé.
- [ ] La navigation vers un processus spécifique fonctionne uniquement pour les utilisateurs autorisés.
- [ ] Un refus d'accès affiche un message compréhensible et ne casse pas le diagramme source.
- [ ] Une cible inexistante ou supprimée est gérée sans erreur non contrôlée.
- [ ] Un clone conserve sa filiation et ses modifications ne changent pas la source.
- [ ] Le comparateur déjà présent permet de comparer le clone à sa source.
- [ ] Les processus existants sans lien externe continuent à s'ouvrir et à s'enregistrer normalement.
- [ ] CI verte : lint, build frontend, build/backend tests et tests ciblés de navigation/permissions.
- [ ] Tests manuels sur l'environnement V2 de test, notamment avec deux profils disposant de droits différents.

## Statut de gel

Cette branche fixe le point de départ de la V2.1. Elle ne doit pas être considérée comme une version de production validée tant que les critères ci-dessus ne sont pas implémentés et vérifiés. Les changements suivants doivent se faire sur une branche de travail dédiée, puis être intégrés à cette branche après revue et tests. Ne pas déployer en production sur la seule base de la création de cette branche.
